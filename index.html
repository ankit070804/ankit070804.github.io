Projects

Assistive communication framework↗

A system that lets someone communicate using only eye blinks, for people who cannot speak or type. Blinks are read from a webcam and decoded as Morse code. The hard part is that Morse by blinking is slow, so the project is about reducing how many blinks a sentence needs.

What I built
  • Blink detection with MediaPipe and OpenCV, converted into Morse code in real time.
  • Sign Language Grammar (SLG), which shortens sentences before they are blinked out, plus a Trie for word prediction and a Digital Twin that logs sessions.
  • Fine-tuned and compared Transformer models for SLG-to-English translation, and chose Flan-T5-small for the best quality and latency trade-off.
Result

Blinks cut by 26.7% on average, and by up to 44.9% for long sentences.

  • PyTorch
  • OpenCV
  • MediaPipe
  • Transformers

UAV localization error prediction↗

When a drone navigates by camera, its position estimate is sometimes badly wrong. This project predicts how large that localization error will be for each frame, and explains every prediction so a person can see why.

What I built
  • A full pipeline on the TartanAir dataset: visual, semantic, depth and motion features per frame, ground-truth error labels from ORB matching and pose comparison, and a Random Forest regressor.
  • SHAP explanations for each prediction, and a local LLM (via Ollama) that turns the top features into a plain-language report.
  • Four different train/test splits, so the score is not inflated by near-duplicate neighbouring frames.
Result and what I learned

R² of about 0.79 on routes the model had never seen (leave-one-sequence-out, range 0.53 to 0.90), versus 0.92 on a random split that leaks adjacent frames. I also found that ORB features account for about 73% of importance, partly because the labels are built from ORB matches, and documented it as a limitation.

  • Scikit-learn
  • SHAP
  • OpenCV
  • Ollama

ModelGuardian: ML drift monitoring↗Team project

Built in 6 hours at the myonsite Ascend hackathon. A deployed model can quietly get worse when live data stops looking like its training data, and ModelGuardian is a pipeline that notices and reacts on its own.

How it works
  • Five small services: a fraud-detection model, a log pipeline, a drift engine, a rollback controller and a live dashboard.
  • Drift is measured with a Kolmogorov-Smirnov test and KL divergence written from scratch, with no drift libraries. A KS value of 0.3 raises a warning, and a critical alert triggers an automatic rollback through GitHub Actions.
  • A traffic generator simulates normal, drifted and adversarial inputs, such as balance spoofing and out-of-bounds values, to test the whole loop.
  • FastAPI
  • TypeScript
  • Next.js
  • GitHub Actions

Explainable deepfake detection↗

Most deepfake detectors give a label and nothing else. This one classifies a face image as real or fake and then shows which parts of the face drove the decision.

  • EfficientNet-B0 fine-tuned with transfer learning in PyTorch to classify faces as real or fake.
  • Grad-CAM heatmaps overlaid on the image, so the prediction can be checked instead of trusted blindly.
  • A Streamlit app where you upload an image and see the verdict and the heatmap together.
  • PyTorch
  • EfficientNet-B0
  • Grad-CAM
  • Streamlit
